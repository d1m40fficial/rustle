# Производительность Rustle

Замеры на машине разработки: Ryzen 5 7500F, 32 ГБ, Windows 11 IoT LTSC 26100,
WebView2 Runtime 156, release-сборка с LTO, если не указано иное.

## Методика

- Стартовые метки пишет само приложение: процесс, окно, content, chrome,
  chrome-ready, visible. Для сравнения берётся chrome-ready.
- Память считается по дереву процессов rustle.exe, включая msedgewebview2.exe.
- **Private** — сумма PrivateMemorySize64, ближе к колонке «Память» в Task Manager.
- **WorkingSet** — сумма рабочих наборов; переоценивает потребление, потому что
  общие страницы DLL и shared memory учитываются в каждом процессе.
- Замеры делаются после 5–6 секунд простоя на новой вкладке.

## M2.1: новая вкладка без WebView

M2.1 переносит страницу новой вкладки в chrome-оболочку. Пустая вкладка больше не
создаёт WebView2; он появляется только при переходе на сайт.

| Сценарий | Private | WorkingSet | Процессов |
|---|---|---|---|
| 2 вкладки, newtab active + lazy example, release | 158.4–162.3 МБ | 343.0–353.3 МБ | 8 |
| 20 пустых вкладок, debug | 172.5 МБ | 364.5 МБ | 8 |

Старт release — 283–390 мс (разброс между прогонами). 20 вкладок создаются быстрым нажатием Ctrl+T; активная
вкладка прокручивается в видимую область. 100 циклов проверены служебным флагом
`--stress-cycles=100`: процесс завершается чисто.

## M2 (исторически): стресс вкладок

| Сценарий | Private | WorkingSet | Процессов |
|---|---|---|---|
| 10 пустых вкладок | 508.4 МБ | 995.8 МБ | 19 |

До M2.1 создание каждого WebView2 блокировало UI, и synthetic 19 Ctrl+T создавал
только 10 вкладок. В M2.1 эта проблема снята для пустых вкладок.

## M3: SQLite и внутренние страницы

SQLite собирается bundled: бинарь вырос с 1.21 до 3.24 МБ, старт не ухудшился
(247 мс). История и закладки открываются в фоновом потоке, UI-поток не блокируется
на запросах. История и настройки живут в внутренних страницах chrome-оболочки,
поэтому не создают дополнительный WebView.

| Сценарий | Private | WorkingSet | Процессов |
|---|---|---|---|
| M3, history + lazy example, release | 161.8 МБ | 351.1 МБ | 8 |
| M2.1, две вкладки, release | 158.4–162.3 МБ | 343.0–353.3 МБ | 8 |
## M3.1: загрузки

DownloadStarting, прогресс и отмена обрабатываются через WebView2 COM. UI загрузок
не создаёт отдельный WebView. Бинарь вырос до 3.31 МБ из-за SQLite и обработчиков
WebView2; старт M3 остаётся 247 мс.
