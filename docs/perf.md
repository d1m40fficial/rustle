# Производительность Rustle

Замеры на машине разработки: Ryzen 5 7500F, 32 ГБ, Windows 11 IoT LTSC 26100,
WebView2 Runtime 156, release-сборка с LTO, если не указано иное.

## Методика

- Стартовые метки пишет само приложение: процесс, окно, content, chrome,
  chrome-ready, visible. Для сравнения берётся chrome-ready.
- Память считается по дереву процессов rustle.exe, включая msedgewebview2.exe.
- **Private** — сумма PrivateMemorySize64, ближе к колонке «Память» в Task Manager.
- **WorkingSet** — сумма рабочих наборов; переоценивает потребление, потому что
  общие страницы DLL и shared memory учитываются в каждом процессе.
- Замеры делаются после 5–6 секунд простоя на новой вкладке.

## Старт

| Версия | Сборка | Chrome-ready |
|---|---|---|
| M0 | debug | 214–252 мс |
| M0 | release | 211 мс |
| M1 | debug | 189–196 мс |
| M1 | release | 238 мс |
| M2 | release | 298 мс |

M1 добавил обработчики навигации, состояния истории и ошибок; старт остаётся
существенно ниже цели 500 мс.

## M2: вкладки

Замер M2 — две вкладки, одна из них ленивая (WebView ещё не создан).
Старт 298 мс, private 208.2 МБ. Активная вкладка добавляет renderer, неактивные
без WebView памяти почти не занимают. Это база для проверки 20 вкладок.
## M2: стресс вкладок

| Сценарий | Private | WorkingSet | Процессов |
|---|---|---|---|
| 10 пустых вкладок | 508.4 МБ | 995.8 МБ | 19 |

Синтетический прогон 19 нажатий Ctrl+T с шагом 600 мс создал только 10 вкладок:
создание каждого WebView2 блокирует UI-поток, события теряются. Это главный
performance-хвост M2. Ленивое восстановление и переключение уже созданных вкладок
работают быстро; ускорение создания — задача M2.1.
